✅ CONFLICT ERROR FIX - PUSHED TO RAILWAY

================================================================================
What was the remaining issue?
================================================================================

Even with proper polling architecture, occasional "Conflict" errors appeared
on Railway because:

1. Old bot instances on Railway weren't fully killing old connections
2. Telegram server still had old getUpdates requests in queue
3. New polling was competing with old connections
4. No retry/recovery mechanism when conflicts occurred


================================================================================
What was fixed?
================================================================================

1. ✅ AGGRESSIVE CONNECTION CLEANUP
   - Reset offset with get_updates(offset=-1) to clear Telegram state
   - This forces Telegram to forget old connection sessions
   
2. ✅ LONGER WAIT TIME
   - Increased from 10s → 15s before polling starts
   - Gives old Railway processes max time to fully die
   
3. ✅ CONFLICT RETRY LOGIC
   - If conflict detected, automatically retry up to 5 times
   - Each retry waits 20+ seconds (forces Telegram timeout)
   - Resets connection state between retries
   
4. ✅ STARTUP SCRIPT (startup.sh)
   - Kills any zombie Python processes before starting bot
   - Ensures 100% clean startup
   - Works with Railway's Docker environment
   
5. ✅ IMPROVED TIMEOUTS
   - poll_interval: 1.0 (less aggressive than 0.5)
   - timeout: 15 (more generous)
   - read_timeout: 15 (handles slow connections)
   
6. ✅ BETTER ERROR REPORTING
   - More detailed logging of retry attempts
   - Shows exactly what's happening during conflicts

How it works now
================================================================================

1. Railway container starts
2. startup.sh runs, kills old processes
3. bot.py starts fresh with no zombie connections
4. Clears all pending updates (offset=-1)
5. Waits 15 seconds for old connections to fully die
6. Starts polling

If Conflict occurs:
1. Catches the error
2. Stops current polling
3. Waits 20 seconds (forces Telegram to drop old connection)
4. Resets connection state with offset=-1
5. Restarts polling
6. Repeats up to 5 times

If still conflicts after 5 tries:
1. Bot logs "Fatal error"
2. Railway restarts bot automatically (per railway.json)
